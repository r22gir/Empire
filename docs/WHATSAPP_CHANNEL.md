# WhatsApp Business Cloud API & Voice Calling — Workroom Max

## Phase 1: Messaging

The channel is off until all four variables are set. Status never includes their values.

| Variable | Role |
| --- | --- |
| `WHATSAPP_ACCESS_TOKEN` | Graph API bearer token for the WhatsApp Business account |
| `WHATSAPP_PHONE_NUMBER_ID` | Phone number id used in `/{id}/messages` and `/{id}/calls` |
| `WHATSAPP_APP_SECRET` | App secret for `X-Hub-Signature-256` |
| `WHATSAPP_VERIFY_TOKEN` | Token Meta sends as `hub.verify_token` |

Empty or missing values leave the channel disabled. `GET /api/v1/whatsapp/status` says `disabled` and lists the missing names.

### Meta setup (Messaging)

1. In the Meta app, add the WhatsApp product and copy the phone number id and a system-user token into the env vars above. Do not commit them.
2. Set a verify token of your choosing and the same value in `WHATSAPP_VERIFY_TOKEN`.
3. Set the callback URL to `https://<your-api-host>/api/v1/whatsapp/webhook`.
4. Subscribe the webhook to the `messages` field.
5. Meta’s GET challenge is answered only when `hub.mode=subscribe` and the verify token matches. The response body is the raw `hub.challenge`.
6. Every POST must carry `X-Hub-Signature-256: sha256=<hmac of the raw body with the app secret>`. A bad signature is rejected and not processed.

## Phase 2: Voice Calls (WhatsApp Business Calling API)

### English (EN)

#### 1. How It Works
- **User-Initiated Calls Only**: The founder (Rafael) places a live WhatsApp voice call to Max's WhatsApp Business number. Meta does **not** allow business-initiated outbound calls from +1 numbers, so outbound calling is not supported or implemented.
- **Webhook Routing (`calls` field)**: Meta dispatches webhook events for `field: "calls"`. The webhook receives `connect` (containing an SDP offer), `terminate`, and `status`.
- **Founder Allowlist Gate**: Incoming calls are checked against `founder_allowlist()` (configured via `backend/app/config/business.json`).
  - Allowlisted numbers: Max accepts the call via WebRTC.
  - Non-allowlisted numbers: The call is immediately **rejected** via Graph API `POST /{PHONE_NUMBER_ID}/calls` with `action: "reject"`. Non-founder callers are never answered.
- **WebRTC Peer & Audio Bridge**:
  - `aiortc` creates a WebRTC peer connection, applies the remote SDP offer, and produces an SDP answer.
  - Max responds to Meta with `pre_accept` followed by `accept` (with the SDP answer).
  - Audio received from WhatsApp (Opus 48kHz mono) is resampled via PyAV to PCM16 24kHz mono and relayed directly to Max's existing xAI Realtime voice brain (`wss://api.x.ai/v1/realtime`, model `grok-voice-think-fast-2.0`).
  - Audio generated by Max (PCM16 24kHz) is resampled to Opus 48kHz and pushed to the WebRTC track back to the caller.
- **Barge-in / Interruption**: When Rafael speaks while Max is answering, server-side VAD detects speech, cancels the active xAI response, and flushes the WebRTC playback buffer immediately.
- **Mid-Call Document Dispatch**: If during the conversation Max creates or inspects an estimate/quote (`get_quote` or quote creation), Max generates the estimate PDF in the background and sends it directly to Rafael's WhatsApp chat window as a `draft` document. Documents are never emailed to clients.
- **Call Lifespan**: Calls hang up cleanly on `terminate` events, on an idle timeout (2 minutes of silence), or when reaching the maximum call duration (default 30 min / 1,800s, configurable via `WHATSAPP_CALL_MAX_SECONDS`).
- **Privacy & Security**: Call start, termination, duration, and reason are logged without logging raw audio or secrets.

#### 2. Environment Variables
| Variable | Description | Default |
| --- | --- | --- |
| `WHATSAPP_CALLING_ENABLED` | Set to `1` to enable WhatsApp voice calls | `0` (off) |
| `WHATSAPP_CALL_MAX_SECONDS` | Maximum allowed duration per call in seconds | `1800` (30 min) |
| `WHATSAPP_TURN_URL` | Optional TURN server URL (e.g. `turn:turn.cloudflare.com:3478` or `turn:your-coturn:3478`) | Unset (uses Google STUN) |
| `WHATSAPP_TURN_USERNAME` | TURN server username | Unset |
| `WHATSAPP_TURN_CREDENTIAL` | TURN server credential/token | Unset |

#### 3. NAT / ICE & Network Considerations
- **Default STUN**: STUN (`stun:stun.l.google.com:19302`) is configured by default.
- **Home NAT / Dell findings**:
  - Behind symmetrical NATs commonly found in residential ISP routers or cellular carrier networks, STUN binding alone may fail to establish direct UDP candidate pairs if port mapping is non-deterministic.
  - In full-cone or standard restricted-cone NAT, STUN succeeds and calls connect directly.
  - For guaranteed 100% reliability from cellular networks or restrictive Wi-Fi behind NAT, configuring a TURN relay is strongly recommended:
    - **Cloudflare Calls TURN**: Low-latency global TURN relay. Pay-as-you-go (~$0.05 per GB of relayed traffic; voice calls use ~0.5MB/min, amounting to < $0.002 per hour).
    - **Self-hosted coturn**: Open-source TURN daemon on a $5/mo VPS (Hetzner / DigitalOcean) with public IP and UDP ports 3478/49152-65535 open.

#### 4. Meta Enablement Steps
To turn on voice calling on Meta's WhatsApp Business Cloud API:
1. **Webhook Subscription**: In Meta App Dashboard > WhatsApp > Configuration > Webhook fields, click **Manage** and subscribe to the `calls` field.
2. **Enable Calling on Phone Number**: Run the following Graph API request:
   ```bash
   curl -X POST "https://graph.facebook.com/v21.0/${WHATSAPP_PHONE_NUMBER_ID}/settings" \
     -H "Authorization: Bearer ${WHATSAPP_ACCESS_TOKEN}" \
     -H "Content-Type: application/json" \
     -d '{
       "calling": {
         "status": "ENABLED",
         "call_icon_visibility": "DEFAULT"
       }
     }'
   ```
3. **Turn on Feature Flag**: Set `WHATSAPP_CALLING_ENABLED=1` in `backend/.env`.

#### 5. Costs & Limits
- **Meta Costs**: Inbound WhatsApp voice calls initiated by users are **free** of Meta messaging fees.
- **xAI Realtime Costs**: ~$0.08 per minute of live audio conversation with `grok-voice-think-fast-2.0`.
- **Limits**:
  - **No outbound calling on +1 numbers**: Meta policy strictly forbids business-initiated outbound voice calls on US (+1) numbers. All calls must be user-initiated.
  - **Production Requirements**: Operating calling on a real WhatsApp business number requires business verification / minimum 2,000 messages/day tier, an approved payment method on Meta Business Manager, and an approved business display name.

#### 1. Cómo Funciona
- **Solo Llamadas Iniciadas por el Usuario**: El fundador (Rafael) realiza una llamada de voz en vivo por WhatsApp al número de WhatsApp Business de Max.   - Números permitidos: Max acepta la llamada a través de WebRTC.
  - Números no permitidos: La llamada se rechaza inmediatamente vía Graph API `POST /{PHONE_NUMBER_ID}/calls` con `action: "reject"`. Jamás se contesta a desconocidos.
- **Conexión WebRTC y Puente de Audio**:
  - `aiortc` establece una conexión peer WebRTC, procesa la oferta SDP de Meta y genera una respuesta SDP.
  - Max responde a Meta con `pre_accept` seguido de `accept` (con la respuesta SDP).
  - El audio recibido de WhatsApp (Opus 48kHz mono) se remuestrea mediante PyAV a PCM16 24kHz mono y se transmite en tiempo real al cerebro de voz de xAI (`wss://api.x.ai/v1/realtime`, modelo `grok-voice-think-fast-2.0`).

- **Interrupción (Barge-in)**: Si Rafael habla mientras Max responde, el VAD del servidor detecta la voz, cancela la respuesta activa de xAI y vacía el búfer de reproducción de audio de inmediato.

- **Duración y Cierre de Llamada**: La llamada finaliza limpiamente al recibir el evento `terminate`, tras 2 minutos de inactividad/silencio, o al alcanzar el límite máximo de duración (por defecto 30 min / 1,800s, configurable con `WHATSAPP_CALL_MAX_SECONDS`).
- **Privacidad**: Se registran inicio, fin, duración y motivo sin almacenar audio ni secretos.

## Chat log, media, and job filing (this edition only)

Workroom Max keeps a **durable chat log**, stores inbound media immediately
(Meta URLs expire), and files photos/documents into this edition’s job folders
when the client is named uniquely.

See also `backend/app/services/max/WHATSAPP_CLOUD.md` for webhook, allowlist, and send-gate rules.

### What is stored

Each inbound and outbound turn lives under this edition’s data directory:

`EMPIRE_DATA_DIR/whatsapp/whatsapp_chat_log.db`

Family editions (Max-e `/data/amp`, Maxine `/data/maxine`) use their own `EMPIRE_DATA_DIR` and never see Rafael’s log or jobs.

Recorded fields:

- sender `wa_id` and display label (from `WHATSAPP_LABELS` / `EMPIRE_DATA_DIR/whatsapp/labels.json`, not committed phone lists)
- direction, timestamp, WhatsApp message id
- type: text, voice-note (marker + stored audio), document (filename + doc/quote id), photo, video, sticker, location, call
- delivery status from Meta status webhooks: `sent`, `delivered`, `read`, `failed` (Meta error code)
- attachment metadata: filename, MIME, size, local path, job slug, filed path

Access tokens, app secrets, verify tokens, and `FOUNDER_PIN` are stripped before write.

### Media

Inbound photos, PDFs/documents, voice notes, video, stickers, and locations are downloaded as soon as the webhook arrives and saved under:

`EMPIRE_DATA_DIR/whatsapp/media/`

Non-image/PDF attachments are served as `application/octet-stream` with `X-Content-Type-Options: nosniff` and `Content-Disposition: attachment`. HTML and SVG are never rendered as a page.

| Variable | Default | Role |
| --- | --- | --- |
| `WHATSAPP_MAX_ATTACHMENT_SIZE_BYTES` | 52428800 (50 MB) | Skip storing oversize files |
| `WHATSAPP_RETENTION_DAYS` | 365 | Purge edition `media/` and `inbox/` (never another edition’s jobs) |
| `WHATSAPP_JOBS_ROOT` | `$EMPIRE_DATA_DIR/jobs` | Edition-scoped job folders |
| `WHATSAPP_LABELS` | `$EMPIRE_DATA_DIR/whatsapp/labels.json` | Founder display names + allowlist extras |
| `WHATSAPP_JOB_ANSWER_TIMEOUT_SECONDS` | 1800 | Parked-file job-answer window |

### Job filing

Photos go to `<jobs-root>/<client-slug>/photos/`. Documents go to `<jobs-root>/<client-slug>/received/`.

Resolution (`app/services/max/doc_lookup.py` + `client_aliases.json`):

1. Caption or message names one client, nickname, address, or quote number → that job.
2. More than one match → **do not guess**. Park in `EMPIRE_DATA_DIR/whatsapp/inbox/` and Max asks which job.
3. No job name → **ask**, never file into a sticky active job.
4. A parked-file reply is consumed only when it clearly names one job, says `skip`, or the ask has timed out. Other text falls through to normal chat.

Existing files are never overwritten (UTC timestamp suffix). Move-to-job / refile accepts only an existing folder under this edition’s jobs root (no path traversal, no new arbitrary folders). That is the only write on the chats page.

### Read API (founder PIN)

All of these require `X-Founder-Pin`. PIN failures are rate-limited. They do not send WhatsApp messages and they do not delete.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/v1/whatsapp/chats` | Conversations, last message, active job |
| `GET` | `/api/v1/whatsapp/chats/{wa_id}/messages` | Page a thread (`limit`, `offset`, optional `q`) |
| `GET` | `/api/v1/whatsapp/chats/search?q=` | Text search |
| `GET` | `/api/v1/whatsapp/media/{attachment_id}` | Download stored media |
| `GET` | `/api/v1/whatsapp/jobs` | Existing job folders for the move-to-job control |
| `POST` | `/api/v1/whatsapp/attachments/{id}/refile` | Move a file into an existing job (`{job_slug}`) |
| `GET` | `/api/v1/whatsapp/chats/{wa_id}/copy` | Plain-text conversation |
| `GET` | `/api/v1/whatsapp/chats/{wa_id}/export` | PDF (or `?format=txt`) |
