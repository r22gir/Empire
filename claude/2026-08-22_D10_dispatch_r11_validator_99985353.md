# DISPATCH R11 — THE VALIDATOR'S BLIND SPOT (DEFECT #1, LOCATED)

R9 is closed. `provider=deepseek, model=deepseek-v4-flash`, proven end to end.

**R9's Phase 3 found defect #1 by accident, and it is not what three rounds
assumed.** From the Phase 3 report:

> the validator at `code_task_runner.py:889-897` only tracks file changes from
> `file_write`, `file_edit`, `file_append`. My prompt asked for the work to be
> done via `shell_execute`, which bypasses the validator's tracking even though
> the file is actually written.

The task **did the work** — file on disk, 30 bytes, exact content, mtime
matching `completed_at`, `executed_tool_calls[0].success: true`,
`returncode: 0` — and was recorded as `error`.

R7 guessed misclassified reads. R8 could not trace it. Both filed the
mechanism under COULD NOT PROBE. **Neither guess was right.** The validator has
an incomplete tracked-tool list, and work done through an untracked tool is
invisible to it.

**What this may mean for the corpus:** "Code task completed without actual file
changes" may often mean *changes were made and not seen*. Some fraction of the
5,679 failures could be completed work recorded as failure. **Do not assume
that fraction — measure it.**

Phase 1 maps and stops. Phase 2 fixes on founder go.

## NOTES FOR THE FOUNDER

- **Step 4 is the one that sets the size of this round.** If most of those
  5,679 failures have empty `files_modified`, the blind spot is real but rare
  and R11 is small. If a meaningful share have non-empty `files_modified`, then
  completed work has been recorded as failure at scale, and the corpus needs
  re-reading rather than re-explaining. I have told M3 not to inflate it — the
  honest answer may well be "rare".
- **Step 5 could be the bigger finding.** Two code-task paths, one writing to
  `openclaw_tasks` and one in-memory only. If the API path's history dies on
  every restart, then `openclaw_tasks` is not a record of what the system did —
  it is a record of one of two paths, and the 5,945/1,443 split describes less
  than we assumed.
- **Step 6 is a one-line question with a large answer.** If no task in 7,390
  rows ever passed the validator with a real file change, the pipeline has
  never worked, and "misconfigured and revivable" was optimistic in a way three
  rounds did not catch.
- **Step 7 restates R9's lesson one layer up.** A tool whitelist asserts what
  it does not know, exactly as a hardcoded model name did. The fix is to look,
  not to remember.
- **Still open, not this lane:** `_provider_key_present` returns True for
  unknown providers (`ai_router.py:334`) — a class defect, own round; moving
  openclaw from deepseek to M3; the three-day May burst on 05-04/05/06 that
  produced 5,895 of 5,904 May failures and has survived three autopsies; the
  doc sweep; and the 102 pre-existing suite failures nobody has looked at.
