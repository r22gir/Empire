# DISPATCH R9 — FIX THE MODEL-NAME LEAK (DEFECT #2)

open and is NOT touched here — single lane.

Traced in `reports/2026-08-22_181935_R8_openclaw_provider_5ce17539.md`: the
`openclaw` wrapper reports its own service name as the model. Four sites.
The enabler is `credenv=None` + `fallback_eligible=True` — a provider with no
credential env can never FAIL a credential check, so it is permanently
"configured", permanently fallback-eligible, and wins by default while hiding
the real deepseek model underneath.

**This is the first WRITE dispatch in this lane.** Phase 1 maps blast radius
and stops. Phases 2 and 3 fire only on founder go, separately.

## NOTES FOR THE FOUNDER

- **Phase 1 step 4 is the one that could grow.** If `fallback_eligible` with a
  null credential check affects which provider serves ordinary MAX traffic —
  not just code tasks — then the model-name leak is the small half of this and
  the routing preference is the large half. I've fenced it off so Phase 2 can
  ship the narrow fix regardless, but read that section before ruling on
  Phase 2.
- **Step 8 guards the class, not the instance.** A test that only checks for
  the string "openclaw" would pass the day someone registers a second wrapper
  with the same shape. `model_default == provider_id` is the actual defect.
- **Phase 3 restarts the backend.** That is now safe — SendGrid already went
  live on 8/22, so there is no pending state change waiting on a restart. It
  will pick up whatever else has accumulated on disk since PID 981771 started,
  which is why step 11 re-checks the R1 pins.

  May failures. That burst has now survived two autopsies unexplained. It is
