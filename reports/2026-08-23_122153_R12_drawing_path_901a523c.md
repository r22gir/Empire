## §1 — THE FREEZE (the actual reproduction)

The dispatch asked me to reproduce "MAX freezing whenever the drawing
tool or router is invoked" and to distinguish (a) true hang, (b) slow
sync render, (c) misroute that looks like a hang. **The answer is (c),
not (a). The drawing-routed path does not deadlock; it returns in
single-digit milliseconds to a few hundred milliseconds.** What
"freezes" is the LLM-tool-loop branch on the *continuation* side.

### Where the "freeze" lives

Probes L and N are the **type-(c) misroute**. Both succeed (HTTP 200,
no exception in the backend), but the wall-clock time is 13s / 21s
because the LLM tool loop calls `sketch_to_drawing` two or three times
in a row and each call fails identically with
`"sketch_to_drawing: text-only with no dimensions. Use
render_shop_drawing with explicit dims, or pass an image path so the
tool can extract measurements."`.

The backend log line for probe N shows the exact root:

```
Aug 23 12:21:34 EmpireDell empire-backend[1113389]:
    minimax failed: KeyError: 'content'
```

That `minimax failed` line is the LLM provider erroring on the *final*
hop. The 2-3 wasted `sketch_to_drawing` invocations each cost
~3-7 seconds of LLM round-trip; the KeyError is just the last gasp
after the retries.

### Mechanism (verified in code, not inferred)

`render_shop_drawing` is registered as the canonical B1 entry point
(`tool_executor.py:2731-2878`). `sketch_to_drawing`
(`tool_executor.py:2881-3163`) is the draw-from-image path; per its
own docstring "MUST NOT emit default dimensions" and refuses text-only
inputs. Both are exposed as MAX tools via the `@tool` decorator.

The router intercepts a small set of patterns (draw a X, draw me X,
item-type + dims, plan-phrase, regenerate/redraw, word-boundary
keyword). When a request DOESN'T match, MAX (LLM) is called. The
LLM has both tools in its roster. When the LLM receives a message
that looks like "give me bench dims" without strong pattern, it
self-routes to `sketch_to_drawing` and gets rejected 2-3 times.

### Py-spy dump

Not needed — the "hang" is not a hang; it's a finite LLM retry chain.
Backend log already shows the trail. (If you want a py-spy dump of
the LLM-loop path, run during a probe-N replay and `sudo py-spy dump
--pid 1113389` — but the chain is reproducible from the log alone.)

### Status

- (a) True hang/deadlock — **NOT REPRODUCED**
- (b) Very slow synchronous render — **NOT REPRODUCED** (render path
  is 30-200ms)
- (c) Misroute that looks like a hang — **REPRODUCED**, two ways:
  - L1 → L2: continuation reply routed to LLM, which retries
    `sketch_to_drawing` 3× (13s)
  - bare dims message with no pending: LLM retries
    `sketch_to_drawing` 2×, then provider errors (21s)

## §4 — THE SEAM (`TestDoctrineGuard`)

### Verbatim quote

`backend/tests/test_drawing_router_to_engine_hotfix4_0b.py:293-323`:

```python
class TestDoctrineGuard:
    """HOTFIX 4.0b (d) — a guard that reminds future contributors
    that E2E tests must enter through the production entry point.
    Mocks for build_drawing_handoff / DrawingHandoff.ready /
    chat-path dispatchers are FORBIDDEN in this module — pin the
    invariant with a static check."""

    def test_no_mock_decorators_in_module(self):
        """No `mock.patch` of drawing-router internals lives in this
        test file. The router integration must be tested via the
        real chat POST."""
        import re
        # Strip the docstring + the canonical-path strings in this
        # module so the guard doesn't trip on its own documentation.
        src = re.sub(r'"""[\s\S]*?"""', '', Path(__file__).read_text())
        # Only flag ACTIVE mock.patch calls (not comments / strings).
        # We require the pattern to be followed by `(...)` to match
        # a real call.
        patterns = (
            r'mock\.patch\(\s*["\']app\.services\.max\.drawing_intent',
            r'mock\.patch\(\s*["\']app\.routers\.max\.router\.build_drawing',
            r'mock\.patch\.object\(.*build_drawing',
        )
        for pat in patterns:
            assert not re.search(pat, src), (
                f"HOTFIX 4.0b (d): mocking forbidden pattern "
                f"{pat!r}. Tests in this module MUST enter through "
                f"the real chat POST. (A test that mocks the layer it "
                f"exists to verify is a defect class — the bug we just "
                f"fixed.)"
            )
```

### What it protects

The guard forbids `mock.patch(...)` or `mock.patch.object(...)`
that targets `app.services.max.drawing_intent` or
`app.routers.max.router.build_drawing*`. The defect class it
defends against is a test that mocks the layer it claims to
verify — e.g. a test that pretends `build_drawing_handoff`
returned a "rendered PDF" without actually exercising the chat
POST. The Jul 24 8:42 AM live repro was caught by exactly this
class of test: the stream-handler interceptor was duplicated, the
mock-based test passed (because both `/chat` and `/chat/stream`
had the same mocked seam), and the production stream handler was
broken (called quarantined `_execute_drawing_handoff`).

The doctrine rule stated in `CLAUDE.md` (lines 46-49): "Chat/stream
duality: any logic in a chat handler lives in ONE shared function
called by BOTH `/api/v1/max/chat` and `/api/v1/max/chat/stream`.
Three separate bugs came from divergent copies. TestDoctrineGuard
enforces this for the drawing seam — extend the pattern, don't
fight it."

### Phase 2 constraint

Per dispatch rule 7: **do not weaken TestDoctrineGuard.** Anything
Phase 2 does must not introduce a `mock.patch` of the drawing
seam. The freeze probe (§1) was done via real `/chat` POSTs, not
mocks — and any Phase-2 fix has to be exercised the same way.

## §5 — THE STANDARD vs REALITY

`EMPIRE_DRAWING_STANDARD.md` (read in full, 71 lines) sets five
hard rules and a list of required views, title-block fields, and
drafting conventions. Cross-checked against the B1 template source.

### Rule 1 — Spec fidelity (no invented dims)

**ENFORCED** at `tool_executor.py:2771-2792` (render_shop_drawing
refuses without product_type + dims) AND `templates/base.py:174-179`
(FamilyTemplate.compute raises ValueError on missing required dims).
AND `templates/roman.py:75-77` (validate_spec returns
MissingFieldsResult, no defaults invented).

**PARTIAL**: when an item-type is detected but specific sub-dims
are absent (e.g. Roman with `width` but no `height`),
`render_spec` returns a missing-list. The router surfaces this as
a question (`router.py:393-407`). This is correct behaviour but
**the LLM then has the chance to misroute the continuation reply**
(§1 probes L/N). The enforcement is at the template boundary; the
router-to-LLM handoff is a known weak spot.

### Rule 2 — One sheet per physical piece

**ABSENT in code**: no per-piece sheet enforcement. The current
pipeline renders one PDF per spec. Multi-piece jobs would
require the founder to issue multiple `render_shop_drawing`
calls. The "SHEET n of N" caption is emitted by `printer.py`
hardcoded as `SHEET B2 · 1 OF 1` (per
`golden_flatfold.py:63` style reference; verified in
`templates/printer.py` rendering pipeline).

### Rule 3 — Layout math closure

**ENFORCED**. Every FamilyTemplate implements `layout_math(spec) →
List[MathLine]` (`templates/base.py:152-154`). Each `MathLine`
carries segments + gaps + closing tolerance. `MathLine.closing_tolerance_in`
(`base.py:107-109`) is `abs(total - target)` and Roman shades
already print `FLUSH BOTH ENDS` vs `WARN: closure off > 1/64" — review slat count`
at `templates/roman.py:174-181`.

The golden reference (`reports/golden_flatfold.py:262-267`) shows
the same pattern: `1 × 38" = 38"`, `9 × 7-1/8" = 64"`,
`FLUSH BOTH ENDS · single panel`. **The roman template matches.**

### Rule 4 — Curved pieces show plan view

**ENFORCED in `b2_renderers.py`** (Roman-only at 94 KB,
substantial B2 implementation including the golden reference style).
The cornice template (`templates/cornice.py`) handles
`double_serpentine`, `pagoda`, `stepped`, `custom_profile` — all
of which require plan view. Verified the
`b2_renderers.render_roman_shades_vector` is the only public B2
entry currently (`templates/__init__.py:60-62`); the other
families' B2 work is partial.

**PARTIAL** for non-Roman families: Drapery/Bench/Valance/Cornice/
Headboard have B1 (numeric + math) but B2 vector renderer only
ships for Roman. The dispatch's note
(`reports/2026-08-19_mclean_map.md` history) reflects this.

### Rule 5 — No output without real rendering

**ENFORCED** at `tool_executor.py:2881-3163` (sketch_to_drawing
refuses text+dims with structured error rather than fabricating
output). `runtime_truth_enforcer` (referenced in the Standard)
was not located by name in this map; per the B2 docstring at
`printer.py:1-37`, the runtime truth enforcement is layered into
the printer pipeline.

## §7 — RECOMMENDED SMALLEST CORRECT FIX

The Phase 1 freeze classification (§1) is **(c) misroute**. The
specific defect is in the LLM tool loop, not in the drawing
router. Three options, in increasing scope:

### Option A (smallest) — block the `sketch_to_drawing` text retry loop

The `sketch_to_drawing` tool docstring already says it refuses
text+dims. The bug is that the LLM retries 2-3 times when it
should pick `render_shop_drawing`. Fix: the router's continuation
path should pre-validate the continuation dims and route them
directly to `render_shop_drawing` without invoking the LLM at
all. Probe L (continuation reply) should be a 50ms render, not
13s.

Risk: low. The change is in `router.py` near the pending-handling
block (`:2411-2424`). No mocks weakened. Doesn't touch the
drawing seam. Existing `test_h57_router_intercept.py` still
applies. Phase 3 acceptance: replay probe L and confirm <200ms.

### Option B — retire the drawing router entirely

The dispatch's open-list item: replace the router with a tool
the LLM picks (giving `render_shop_drawing` to the LLM and
removing the pre-model intercept). This eliminates the
duplication-of-decision risk and makes the LLM the single
authority on routing.

Risk: medium. Three known side effects:
1. The LLM must be told (via system prompt) that drawing intent
   means "call `render_shop_drawing`, not `sketch_to_drawing`".
2. The "any non-continuation releases pending" rule needs a
   non-router replacement (the LLM has to decide).
3. Negative fixtures (probes B/C — "what is a drawing") stop
   routing via the router, but currently they reach the LLM
   anyway post-H57, so the user-visible behaviour is the same.

### Option C — port the B2 vector renderer to non-Roman families

Larger scope; outside this round per the dispatch's
scope-by-Phase-1 rule. The Phase 1 finding here is that Roman
shades is the only family with full B2 (vector + QC gates + plan
view + side section); the other five families are B1 only (numeric
math + missing-list). Any "MAX must produce today's document
formats" round that touches Workroom non-Roman items will hit
this gap.

Risk: high. Each family is its own geometry, its own
QC-gate scope, its own font/colour decisions. Phase 3 acceptance
for Option C is multi-week.

### Recommended: Option A

Option A is the smallest correct fix. It is:
- ROUTER-LOCAL: `router.py:2411-2424` (chat) and `:3241-3248`
  (stream) — the existing pending-handling block. After
