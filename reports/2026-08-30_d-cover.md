## Defects

### 1. OPEN ITEMS counts user-supplied check list, not auto-augmented PENDING

`mclean_drapery_set_generator.py:1055` (cover index):
```python
rows.append((f"{n:02d}", r["name"], str(wins) if wins else "wall",
             str(len(r["check"]))))
```

The 4th column ("OPEN ITEMS") is hardcoded to `len(r["check"])`. It does NOT count the auto-augmented `pending_labels` (built in `room_sheet()` from data rows with `{"pending": True}`).

**Effect**: When a spec relies on the auto-augmentation convention (the standard pattern), the cover index reads 0 even when room sheets carry N PENDING bullets.

**Becky realization**: Cover reports `0` for W1/W2/W3 while sheets carry 7 PENDING bullets (DEDUCTION + MOUNT on all three rooms, OPENING WIDTH on W3).

### 2. Trailing separator when client_loc is empty

`mclean_drapery_set_generator.py:cover()` line ~999 (cover header):
```python
"FOR " + spec["job"]["client"] + "  \u00b7  " + spec["job"]["client_loc"]
```

And `mclean_drapery_set_generator.py:cover()` line ~1015 (JOB block):
```python
("CLIENT", spec["job"]["client"] + "  \u00b7  " + spec["job"]["client_loc"])
```

Both concatenate `"  \u00b7  "` + `client_loc` unconditionally. When `client_loc == ""`, the result has a trailing separator that renders as `" \u00b7"` (e.g., `"LAUREN BASSETT \u00b7 LB DESIGN \u00b7"`).

**Effect**: Specs that omit `client_loc` get a visibly dangling bullet on the cover header and the JOB/CLIENT row.

**Becky realization**: client_loc was set to `""` to keep the cover header inside the page frame after the client name was expanded to `"LAUREN BASSETT \u00b7 LB DESIGN"`. The trailing `·` then appeared on both the cover header and the JOB/CLIENT row.

## Proposed fix

### Fix 1 — count pending data rows directly in cover

The simplest fix is to count `pending` data rows per room inside the cover loop, matching the same definition that drives the FIELD CHECK augmentation in `room_sheet()`:

```python
# In cover(), replace the row.append line:
for n, r in enumerate(spec["rooms"], start=2):
    wins = sum(1 for p in r["panels"] for i in p.get("items", [])
               if i["kind"] == "window")
    pending_n = sum(1 for tup in r.get("data", [])
                    if len(tup) >= 3 and isinstance(tup[2], dict)
                    and tup[2].get("pending"))
    # Use pending_n where it exists; fall back to len(r["check"])
    # so byte-identity holds for SPEC_MCLEAN (no pending data rows).
    open_items = pending_n or len(r.get("check", []))
    rows.append((f"{n:02d}", r["name"],
                 str(wins) if wins else "wall",
                 str(open_items)))
```

The `or` is the byte-identity safeguard: `SPEC_MCLEAN` has no `{"pending": True}` data rows, so `pending_n == 0`, and the existing `len(r["check"])` path is taken.

### Fix 2 — suppress separator when client_loc is empty

A two-line helper, placed inside `cover()` (no module-scope pollution):

```python
client_str = spec["job"]["client"]
if spec["job"].get("client_loc"):
    client_str += "  \u00b7  " + spec["job"]["client_loc"]
```

Then use `client_str` at both sites:
```python
o.append(T(30 + tw(spec["job"]["project"], 26.0, SERIF, True, ls=1.2) + 16, 78,
           "FOR " + client_str, 9.0, "start", MUTE, MONO, bold=True, ls=1.4))
# and
("CLIENT", client_str),
```

Byte-identity for `SPEC_MCLEAN`: `client_loc = "McLEAN, VA"` is truthy, so the separator is preserved. No change.
