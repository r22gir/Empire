## FOUND
- The Drapery R1 render drew the side-section drape at a VISIBILITY CONSTANT
  (drape_depth in sheet inches, not at true scale). The first live raster
  gate run measured **mean drape depth 1.028" (sheet)** vs the
  DRAPE_PROJECTION_IN[pinch_pleat]=(2.0,3.0) bounds (real inches). The
  1.028 was a real catch — the gate was reading sheet inches and comparing
  to real-inch bounds. Two bugs in one.
- A second-order bug: the wall line at `wall_x + 0.30` sat 0.30" in front
  of the drape back edge, so the raster gate's leftmost-inked-pixel scan
  picked up the wall line as the depth boundary (≈ 9.5" real — far outside
  the 2-3" bound).
- A third bug: the title column truncated `fabric_name` to 20 chars,
  cutting "Nympheus Velvet Emerald" → "Nympheus Velvet Emer". Doctrine
  placeholder "TBC — CONFIRM BEFORE CUT" was at risk.
- A fourth bug: the LAYOUT MATH was truncated to 35 chars mid-word, so
  the closure equation read "4 × 19-3/4" + 2  ·  FLUSH BOTH ENDS"
  (missing "× 4"" returns and chopped note).
- A fifth bug (test infrastructure): the broken `_overlay_sail_drapery`
  had orphan code from a previous merge — it drew a Roman Shade body
  + Roman Shade title column on TOP of the Drapery canvas. The
  negative-fixture helper produced a broken PDF that failed on
  `text-over-geometry` (not on `drapery-plumb`/`uniform-depth`), so the
  strict negative-fixture contract (fail on drapery-plumb/uniform-depth
  ONLY) was never actually being tested.

## CHANGED

### `backend/app/services/drawing/templates/b2_qc.py`
- **Gate D-R2-1 (`_check_drapery_plumb`)**: extracted `_parse_scale_factor`
  helper for shared use with `_check_elevation_scale_truth`. The gate now
  parses the SCALE row from the title column, converts measured depth
  via **px → sheet inches (÷ DPI=150) → REAL inches (÷ scale_factor)**,
  and compares to `DRAPE_PROJECTION_IN[heading]` bounds in real inches.
  PLUMB and UNIFORM DEPTH remain scale-invariant shape checks in sheet
  inches. Failure messages explicitly state the unit chain so a future
  bug can't re-introduce the unit-mismatch silently.
- **Gate D-R2-1 viewport handling**: identifies the main drape as the
  LARGEST FILLED rect in the side viewport (excluding the viewport
  frame), then restricts the row scan to only that rect's y range.
  Without this, the DETAIL A callout content (drawn at magnified scale
  for legibility — different scale than the main drape) would corrupt
  the depth measurement. Also excludes a 3-px border from each side of
  the crop to skip the viewport-frame lines.
- Pre-caches `page0.rects` inside the pdfplumber context (pdfplumber
  invalidates lazy attrs after close).

### `backend/app/services/drawing/templates/drapery_render.py`
- **TRUE projection at scale**: drape depth is now drawn at
  `drape_depth_real × scale_factor` (real inches × scale), NOT at a
  visibility constant. The previous R1 bug used `drape_depth_real` directly
  as sheet inches (≈ 60× too big at typical scales — would have failed
  the depth-bounds check at 2.5/0.043 ≈ 58" real for an 87" drape).
- **Wall line removed from main side section**: was at `wall_x + 0.30`,
  corrupting the raster gate's depth measurement (added ~7" real).
  Rod + floor + ceiling are sufficient room-context indicators.
- **DETAIL A callout** added when the true-scale drape is too thin
  to read (`drape_depth_sheet ≤ 0.12"`). Magnification factor brings
  the rendered detail depth into the readable band [0.50, 0.80]" sheet.
  Detail border drawn as 4 LINES (not rect) so the text-over-geometry
  gate (which checks rects only) doesn't false-fire on internal labels.
  Label inside box top: `"DETAIL A — DRAPE ({mag:.1f}× · true {depth:.2f}")"`.
  No R4 lateral exaggeration.

## UNITS CHECK (per directive)

The raster gate's depth measurement follows this chain:

```
pixels (px, 150 DPI rasterization)
  ÷ 150 DPI
= sheet inches (what's on paper)
  ÷ scale_factor (sheet-in per model-in, parsed from SCALE row)
= REAL inches (what the drape is in the world)
```

For an 87" × 84" Drapery at scale 1" = 1'-11-5/16" (= 23.3125 model-in per sheet-in):

| Stage                    | Value          | Notes                                  |
|--------------------------|----------------|----------------------------------------|
| Measured pixels          | 16 px          | leftmost → rightmost ink in side row |
| Sheet inches             | 0.107"         | ÷ DPI=150                              |
| **Real inches**          | **2.49"**      | ÷ scale_factor 0.0429                 |
| DRAPE_PROJECTION_IN[pinch_pleat] | (2.0, 3.0)  | bound check (PASS — within bounds) |

The plumb front edge has stddev ≈ 0.04" sheet (well under the 0.15" tolerance).
The uniform-depth ratio is 0% (top-band mean = bottom-band mean).

For ripplefold the bounds would be (3.5, 4.5)" real; with the same
scale factor the rendered depth is `4.0 × 0.0429 = 0.172"` sheet
(≈ 26 px) — visible at true scale, so no DETAIL A is needed.
