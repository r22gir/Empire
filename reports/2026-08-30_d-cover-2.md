## Defect

D-COVER (`022fd7e`) introduced a sum for the cover's OPEN ITEMS column:

```python
pending_n = sum(1 for tup in r.get("data", [])
                if len(tup) >= 3 and isinstance(tup[2], dict)
                and tup[2].get("pending"))
open_items = pending_n + len(r.get("check", []))
```

This was a deliberate departure from the earlier `or` variant because Becky W1 carries both pending data slots AND a non-empty check list (the bench construction rule, per option 1).

**Effect**: The bench block is settled content, not an open item, but it counts toward W1's OPEN ITEMS because it lives in `r["check"]`. W1 therefore reads 3 instead of 2 (the actual pending-slot count for W1).

**Becky realization**: cover reads `3 / 2 / 3 = 8`, of which 7 are pending slots and 1 is the bench block counted as an open item. This is factually correct given the current count semantics but semantically wrong — the bench is settled, not open.

## Why the bench lives in `r["check"]`

The bench block is multi-line:

```
BENCHES — 2 EA, RYANN STYLE, 22 x 18 x 15
Box joint frame. One continuous fabric wrap, no channels, no
tufting, no caps. COM: Vervain PINDO 04, bolt 0086, 5.00 yd —
customer supplied, no fabric line.
```

The only multi-line per-room field in the McLean generator is `r["check"]`. The `fabric_strip` is single-line and cannot hold the block verbatim (separate STOP earlier in this session — `room_sheet():987-988` calls `T()` once). The FIELD CHECK column renders `r["check"]` items as wrapped paragraphs via `wrap()`, which is why the bench landed there.

## Proposed fix

Add a `{"settled": True}` marker on check items that should be excluded from the OPEN ITEMS count. The cover filters settled items before counting. `room_sheet()` extracts the text and renders it identically.

```python
# In cover() — replace the open_items line:
for n, r in enumerate(spec["rooms"], start=2):
    wins = sum(1 for p in r["panels"] for i in p.get("items", [])
               if i["kind"] == "window")
    pending_n = sum(1 for tup in r.get("data", [])
                    if len(tup) >= 3 and isinstance(tup[2], dict)
                    and tup[2].get("pending"))
    # Settled check items render in FIELD CHECK but don't count toward
    # OPEN ITEMS. Plain-string check items (the default) do count.
    open_check_n = sum(1 for c in r.get("check", [])
                       if not (isinstance(c, dict) and c.get("settled")))
    open_items = pending_n + open_check_n
    rows.append((f"{n:02d}", r["name"], str(wins) if wins else "wall",
                 str(open_items)))
```

And in `room_sheet()`, extract the text from dict entries:

```python
# room_sheet() — augment the room_check construction:
room_check = []
for entry in r.get("check", []):
    if isinstance(entry, dict):
        room_check.append(entry.get("text", ""))
    else:
        room_check.append(entry)
for lab in pending_labels:
    room_check.append(f"{lab}: PENDING - confirm on site")
```

The settled check item takes the form:

```python
r["check"] = [
    {"settled": True, "text": (
        "BENCHES \u2014 2 EA, RYANN STYLE, 22 x 18 x 15\n"
        "Box joint frame. One continuous fabric wrap, no channels, no\n"
        "tufting, no caps. COM: Vervain PINDO 04, bolt 0086, 5.00 yd \u2014\n"
        "customer supplied, no fabric line."
    )},
]
```

**Byte-identity safeguard for SPEC_MCLEAN**: SPEC_MCLEAN's check items are plain strings (no `{"settled": ...}` dicts). The `isinstance(c, dict) and c.get("settled")` filter ignores all string entries, so the count is unchanged. And `room_sheet()`'s new extraction loop renders strings identically to the previous behaviour.

For Becky: W1's check list becomes `[{"settled": True, "text": BENCH_BLOCK}]` and the count for W1 drops from 3 to 2.

## Why option 2

Three options were on the table when D-COVER landed (flagged, not solved):

1. **New field** `r["notes"]` (or similar) — excluded from the OPEN ITEMS count. Generator change adds a new field with new rendering. Heavier surface area.
2. **Marker on existing check items** — minimal change, matches the existing `pending`/`settled` pattern. ✓ *this dispatch*.
3. **Drop the bench from W1 check** — accepts the multi-line cost, moves the bench to `fabric_strip` after adding multi-line support. Requires revisiting option 1 from the earlier STOP analysis; invasive.

Option 2 is the minimal change and the cleanest fit with the existing convention. Recommend it.
